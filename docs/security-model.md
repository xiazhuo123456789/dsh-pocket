# 安全模型

## 信任边界

```
┌─────────────────────────────────────────────────────────────┐
│  你的电脑                                                   │
│  ┌────────────────────┐   ┌──────────────────────────────┐  │
│  │ DeepSeek Harness   │   │ agent：读写文件、执行命令    │  │
│  │ 远程控制面          │──▶│ 完全控制权                   │  │
│  └────────────────────┘   └──────────────────────────────┘  │
│            ▲                                                │
└────────────┼────────────────────────────────────────────────┘
             │ 设备凭据（可撤销）
┌────────────┼────────────────────────────────────────────────┐
│  ┌─────────┴──────────┐                                     │
│  │ DSH Pocket (手机)  │  ← 与电脑同等权限的控制器           │
│  └────────────────────┘                                     │
└─────────────────────────────────────────────────────────────┘
```

**关键事实：配对的设备等价于完整控制权。**

这不是本应用的设计选择，而是 DeepSeek Harness 远程控制面的既定语义。配对成功后，
该设备可以：提交任务、读取会话内容、停止任务、回答审批、修改设置、读取凭据配置。
`/api/pair`、`/api/update`、`/api/plugin-manager` 是唯一被挡在外面的三个面，挡住的
原因是它们必须物理在本机执行。

所以：**只配对你自己持有的设备。** 不要因为「它只是个手机 App」就放松警惕。

## 传输

| 场景 | 加密 |
| --- | --- |
| 公网隧道（`https://*.trycloudflare.com`） | TLS，Cloudflare 边缘终结 |
| 局域网直连（`http://192.168.x.x`） | 明文 |

局域网明文是刻意的取舍：在自家 Wi-Fi 上跑 TLS 需要自签证书并让手机信任，成本高于收益。
但要知道这意味着**同网段的其他人可以看到流量内容**。在咖啡厅、酒店、公司访客网络里，
用隧道而不是局域网直连。

`network_security_config.xml` 允许明文仅是为了这个场景，没有对公网域名放开。

## 凭据

### 电脑侧

- 设备 ID 与签发记录在 DeepSeek Harness 的 `remote-web-ui-devices.json`
- 可随时撤销，撤销立即生效
- 配对令牌一次性、有有效期

### 手机侧

- 设备 ID 存在 `EncryptedSharedPreferences`（AES-256-GCM，密钥由 Android Keystore 保护）
- 不写日志、不进崩溃报告、不导出
- `allowBackup=false`：不会被云备份带走
- 「断开并清除」删除本机凭据；**不撤销**电脑侧授权

### 手机上没有的东西

- ❌ DeepSeek API Key
- ❌ Harness 内部令牌
- ❌ 电脑的 `.credentials.yaml` 内容
- ❌ 会话内容持久化（重开应用从电脑重新拉取）

## 应用做了什么防护

| 措施 | 说明 |
| --- | --- |
| 加密存储凭据 | `EncryptedSharedPreferences` |
| 禁止备份 | `allowBackup=false` + `dataExtractionRules` 全排除 |
| 相机权限只在扫码时申请 | 只有按下「扫一扫」才请求，见下方说明 |
| 不申请存储权限 | 相册那条路走系统图片选择器（`PickVisualMedia`），拿到的是用户主动选的那一张 |
| 显式错误而非乐观假设 | 网络失败不假装成功 |
| 通知里的审批按钮受限于活跃连接 | 进程被杀后按钮失效而不是静默丢弃 |

### 关于相机权限（0.4.0 起新增）

0.4.0 之前这个应用**不申请**相机权限，扫码只能从相册选截图。但那条路要求用户先把
二维码弄到手机上 —— 对「手机控制电脑」这个前提而言是荒谬的一步，所以现在补上了
摄像头扫码，也就不可避免要 `CAMERA` 权限。

做了这些约束：

- **只在用户按下「扫一扫」时请求**，不在启动时、不在配对页一打开就弹。
- **拒绝不是死路。** 拒绝后会说明原因并给「用相册」的退路，相册那条路完全不需权限。
- **画面不出设备。** 帧交给 ML Kit 的**内置**模型在本地解码，不上传、不落盘、不解码
  二维码以外的任何内容。选内置模型（`com.google.mlkit:barcode-scanning`）而非
  `play-services-mlkit-barcode-scanning` 也有安全含义：后者首次使用要联网下载模型，
  而「正在配对」这一刻往往正是网络没配好的时候，下载失败就等于功能不可用。
- **配对完成后相机立即释放**（`ProcessCameraProvider.unbindAll()` + 生命周期绑定），
  不会在后台持续占用摄像头。

`AndroidManifest.xml` 里 `CAMERA` 权限配了：

```xml
<uses-feature android:name="android.hardware.camera" android:required="false" />
<uses-feature android:name="android.hardware.camera.autofocus" android:required="false" />
```

`required="false"` 是刻意的：没有摄像头的设备照样能装、能用粘贴链接和相册两条路，
Play Store 也不会把它们过滤掉。代价是应用必须自己处理「点了扫一扫但设备没摄像头」
的情况，`CameraScannerDialog` 在 `ProcessCameraProvider` 拿不到时给的是明确的错误
文案而不是崩溃。

## 应用**没有**做什么（不承诺）

- ❌ 不提供沙箱。手机发起的任务在电脑上以你的用户身份运行。
- ❌ 不改变 DeepSeek Harness 的审批策略。会话是 `ask` 还是 `never` 由电脑决定；
  设为 `never` 时手机不会收到审批请求，任务直接执行。
- ❌ 不阻止 agent 做危险操作。审批是唯一的拦截点，且只在你配置了 `ask` 时存在。
- ❌ 不保证加密能消除所有风险。设备被物理控制、系统被入侵、隧道被中间人攻击，
  都超出本应用能防护的范围。
- ❌ 不做端到端加密。公网隧道场景下 Cloudflare 能看到明文（TLS 在其边缘终结）。

## 威胁模型

### 已考虑

| 威胁 | 缓解 |
| --- | --- |
| 手机丢失 | 电脑端撤销设备；凭据在 Keystore 保护下 |
| 配对链接泄露 | 一次性令牌 + 有效期；生成后尽快使用 |
| 局域网嗅探 | 建议用隧道；文档明确说明明文风险 |
| 恶意应用读取凭据 | EncryptedSharedPreferences + 应用私有目录 |
| 通知栏泄露敏感内容 | 通知只显示「需要审批」，不显示参数详情 |
| 误触停止/审批 | 停止有二次确认；审批显示工具名与理由 |

### 未考虑（超出范围）

- 电脑本身被入侵
- DeepSeek Harness 或其插件的漏洞
- Cloudflare 账号被攻破
- 用户主动把凭据交给他人
